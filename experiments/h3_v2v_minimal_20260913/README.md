## 只读预检发现

1. FL2VA 和 Ref2VA 的 Transformer 配置、参数键集合一致：50 层、56 个 attention heads，每头维度 128；两者各有 535 个索引键、13 个 Transformer 分片。这只证明结构可对照，不证明参数相同或迁移后质量不变。
2. VDN 增量文件存在；完整模型路径还需要正确加载线性参数和 LoRA，并确认缩放。
3. 当前 VDN 开关默认关闭，移植仅支持 TP=1；现成完整服务脚本则使用 8 卡，不能直接照搬或与历史耗时比较。原始 A 的 USP4、文本编码 TP4、VAE tile4 静态检查通过，但 B 的 Softmax/线性分支绕过了必要的序列并行通信，不能直接打开 USP4；需另行适配和数值核验。
4. `OpenVDNLayout` 只显式描述 target 区间，没有 source 帧映射。现有 softmax 将所有非 target token 当作 global，source 也因此全局可见。
5. 现有线性分支直接处理的是 target 内部帧及 text，并没有显式将 source 帧写入线性状态。阶段一保留它，不应声称它已经直接补全所有 source 全局访问。
6. 完整链路的动态 latent shape、增量权重加载与单卡卸载内存开销仍需验证。五层随机输入脚本不能证明全视频跑通。
7. 参数文件头推算：H3 DiT 约 61.73 GiB，VDN 线性增量约 3.99 GiB，合计约 65.71 GiB，超过单卡 64 GiB，尚未包含激活。因此需分层卸载或已验证的并行适配；这不是实测 OOM。文本编码器另有设备内存约束。
8. 本地五层脚本合并 LoRA 的有效缩放为 1，但增量文件无 alpha/r 元数据，仍须与官方实现核对。原始 H3 QKV 参数有按 head 分组与加载重排，不应直接对原始 fused 权重按整块 Q/K/V 切分合并。
